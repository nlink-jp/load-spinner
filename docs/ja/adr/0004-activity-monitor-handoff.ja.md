# ADR 0004: パネルのフッターからアクティビティモニタへ引き継ぐ

- Status: Accepted
- Date: 2026-08-23

## Context

メニューバーのインジケーターは 1 つの問い — *このマシンは今どのくらい忙しいか* — に答え、しかも
意図的に数値なしで答える（ADR 0001）。クリックするとステータスパネルが開き、同じ問いに少しだけ
精度を上げて答える: CPU/GPU のライブなパーセンテージ、メモリ使用量、そして 3 分間の履歴である。

その次に来る問いはいつも同じで、このアプリはそれに答えられない: **何で忙しいのか？** プロセスを
名指しするにはプロセスの一覧、プロセス単位のサンプリング、並べ替え、そして行に対して操作する手段
が必要になる — それはアクティビティモニタであり、すでに OS に付属し、すでに馴染みがあり、そして
利用者がもともと向かおうとしていた先である。その一部でも作り直すのは、メニューバーのスピナーの
範囲外である。

欠けていたのは引き継ぎだった: 利用者はパネルを離れ、Spotlight か Launchpad でアクティビティ
モニタを探し、一からやり直さなければならなかった。

## Decision

macOS のアクティビティモニタを起動する（あるいは前面に持ってくる）操作部を 1 つ、ステータス
パネルのフッターに加える。

- **ステータス面のフッター**、終了 の隣 — パネルにすでにある「ここを離れる」操作の行である。表の
  面が、利用者が反応している表示を出している面なので、引き継ぎはその真下に置く。
- **アイコンのみ**（`chart.bar.xaxis`）で、`.help` のツールチップと、完全な
  「アクティビティモニタを開く」 を持つ `accessibilityLabel` を添える。綴った文字列は収まらない:
  パネルの固定幅 340 pt では、バージョンのテキストと文字ラベル付きのボタンと 終了 でボタンが
  切り詰められる（見積もりではなく、フッターを画面外にレンダリングして確認した）。
- **起動時に一度だけ探し、見つからなければ無効な操作部へ degrade する。** `AppDelegate` は起動時に
  `resolveActivityMonitorURL` でアクティビティモニタを解決し — まず Launch Services
  （`com.apple.ActivityMonitor`）、次に `/System/Applications/Utilities/Activity Monitor.app`
  へのフォールバック — パネルにクロージャを渡す。どちらの探索でも見つからなければ `nil` を渡す。
  `nil` はボタンを無効にし、ツールチップを理由を述べるものに変える。黙って何もしないボタンを
  差し出す代わりである。これは GPU の degrade 経路（ADR 0001）と同じ形である。
- **起動の前にポップオーバーを閉じる。** そして起動がアクティビティモニタをアクティブ化するので、
  前面に出てきたアプリの後ろに古い transient なポップオーバーを残すのではなく、利用者が向かう先
  にフォーカスが着地する。
- **探索は `LoadSpinnerCore` の純関数である。** 両方の探索は注入され（アプリでは
  `NSWorkspace`/`FileManager`、テストではスタブ）、優先順位の規則と見つからない場合を単体テストで
  押さえたまま、AppKit の層は薄く保たれる。

## Consequences

- `LoadSpinnerCore` に純関数 1 つとそのテストが増える。アプリターゲットには `NSWorkspace` を
  薄く包む `ActivityMonitor` が増える。既存の `onQuit` と並んで、クロージャが `AppDelegate` →
  `PanelContainer` → `PanelView` へ通される。
- 新しい設定も、新しい権限も、新しいサンプリングも無い。他のアプリを起動するのに entitlement は
  要らず、アクティビティモニタ自身の権限はそのアプリの問題である。
- パネルは一目見ること以外に存在理由を 1 つ得た — 詳細表示への経路にもなった。設定面は手つかず
  である。
- フッターはこれで 3 項目の幅になった。ここにこれ以上何かを加えるなら別の置き場所が必要になるか、
  バージョンのテキストが場所を譲ることになる。

## Alternatives considered

- **ステータス項目の右クリック `NSMenu`**（アクティビティモニタ / 設定 / 終了）。1 クリック近く、
  macOS の標準的な言い回しでもあるが、目に見えない: 右クリックで何かが起きるとは画面上の何も
  言っていないので、そこにしか置かれていない操作部は、ほとんどの利用者が見つけない操作部である。
  ステータス項目のクリック処理を 2 つに分けることにもなる。*将来の追加* としては排除していない —
  これを変えずにその上に重ねられる。
- **CPU / GPU / メモリのカードをクリックできるようにする。** 原理的には優雅だが（気になっている
  数値を押す）、カードには押せるという手がかりが無いので、そもそも見つけてもらうにはホバーの
  スタイルとヒントが要る — 置き換えるはずのボタンより UI が増える。
- **上位のプロセスをパネル自身に表示する。** これを正直にやるならプロセス単位のサンプリング、
  並べ替えできる表、kill の操作 — 340 pt のポップオーバーの中に、より悪く作り直したアクティビティ
  モニタである。不正直な版（静的な上位 3 件の一覧）は両方の悪いところを取る: 行動するには足りず、
  そう見えるには足りている。
- **`open(1)` や `NSWorkspace.open(_:)` でパスからアクティビティモニタを開く。** 動くが、OS が
  自由に移せる場所をハードコードすることになり、成功するかどうかを事前に知る手段が無い。
  Launch Services は両方に答える。
