# ADR 0002: メモリは充填ゲージ（レベル）であり、スピナー（レート）ではない

- Status: Proposed
- Date: 2026-07-15

## Context

今日の load-spinner は 1 つの抽象の上に成り立っている: **正規化された負荷（0...1）→ 回転速度
（RPM）** である。`rotationsPerMinute`（`Speed.swift`）、`IndicatorPlan.load`
（`Indicator.swift`）、`SpinnerView` の周回する点灯部分は、いずれもすべてのインジケーターが
*レート* — 「これは今どのくらい忙しいか」 — を動きとして表すことを前提にしている。

3 つ目のインジケーターとしてメモリを加えたい。しかしメモリはレートではない。CPU と GPU は
**フロー**量（ある区間における忙しさの割合）だが、メモリは**ストック**量（この瞬間にプールが
どれだけ埋まっているか）である。利用者がメモリインジケーターに求めるのは「どれだけ速いか」では
なく「余裕がどれだけ残っているか」 — 絶対的なレベルである。

導出を左右する macOS のメモリに関する事実が 1 つある: **「空きメモリ」は誤解を招く。** macOS は
遊んでいる RAM をファイルキャッシュで意図的に埋めるため、マシンが健全であっても `free / total` は
ほぼゼロに読める。「どれだけ埋まっているか」を忠実に表す数値は、アクティビティモニタ流の
*使用済み* メモリ、すなわち `host_statistics64(HOST_VM_INFO64)` のページカウンタから導いた
`(App + Wired + Compressed) / physical` である。

macOS はメモリの *プレッシャー* レベル（`kern.memorystatus_vm_pressure_level` → normal /
warning / critical）も公開している。当初はこれでゲージを色付けしたが、利用者には直感的でないと
分かった — 「使用率は高いのにプレッシャーは normal だから大丈夫」は理解しづらいメンタルモデルで
ある — ので、代わりに色は使用率に従わせる（Alternatives 参照）。

## Decision

メモリを既存の**レートスピナー**と並ぶ独立した視覚種別 — **レベルゲージ** — として導入し、
*回るものはレート、埋まるものはレベル* という視覚言語を確立する。

- **充填 = 使用率。** ゲージのストロークは、アクティビティモニタ流の使用率（0...1、連続的な
  絶対値）に比例して埋まる。
- **色 = 固定アクセント、または使用率グラデーション。** ゲージの色の軸は CPU/GPU スピナーと同じ
  2 択の `ColorMode { fixed, gradient }` だが、独立した `memoryColorMode` 設定として持つ:
  固定アクセントか、使用率グラデーションである。デフォルトは `gradient` で、初期状態から色が
  「どれだけ埋まっているか」 — 利用者がメモリゲージから読み取る唯一のこと — を補強する。
  （プレッシャー帯による色付けを先に試したが、直感的でないので取り下げた。Alternatives 参照。）
- **メモリは独自のグラデーション停止点を持つ（青 → 緑 → オレンジ → 赤）。** CPU/GPU の負荷は
  「少ないほど穏やか」と読めるので、そのグラデーションは冷たいティールから始まって暖色に向かう
  だけである。メモリには *スイートスポット* がある: ほとんど使われていない RAM は活用されて
  いない（「冷えた」青）、健全な中域の使用は緑（0.5）、高域だけが暖色に向かう（0.75 で
  オレンジ、1.0 で赤）。ここで負荷のグラデーションを流用すると 50% がアンバーになり —
  まったく健全な値に対して警告的である — ので、メモリは代わりに `memoryGradientStops` を通す。
- **静止しており、アニメーションしない。** ゲージはアニメーションタイマーに参加しない。その静止
  そのものがメッセージである（「これは水位であって速度ではない」）。充填の変化は ~0.3 秒で
  なめらかにイージングする。絶え間ない動きは無い。
- **独立したトグルであり、表示モードではない。** 新しい `showMemory` 設定は `DisplayMode`
  （max / cpu / gpu / both）と直交する。メモリは CPU の代わりに選ぶ選択肢ではなく *追加* で
  ある — だからトグルにし、`DisplayMode` の組み合わせは変えない。オンのとき、リングは CPU/GPU
  インジケーターの右に描かれる。
- **枠の語彙を流用する。** ゲージは丸／角丸四角の枠（`IndicatorShape`）を流用してスピナーと
  視覚的に並ぶが、周回するダッシュではなく `strokeStart/strokeEnd` の充填として描かれる。
- **メニューバーには数値を出さない。** メニューバーのゲージは CPU/GPU スピナーと同じく形だけで
  ある。~22px のリングの横に数値を置く試作は、読むには窮屈すぎるとして取り除いた
  （Alternatives 参照）。パネルのドーナツが、場所のある穴の中にパーセンテージを載せる。
- **Core は純粋でテスト可能なまま。** `MemorySnapshot`（生のページカウンタ + 物理総量）と、
  純関数 `memoryReading(_:) -> MemoryReading`（使用バイト数／使用率）を追加し、`cpuUsage` と
  `gpuUtilization(fromPerformanceStatistics:)` に揃える。`MemorySampling` プロトコルが
  `host_statistics64` の読み取りを包むので、導出はカーネルに触れずに単体テストできる。
- **パネル。** SwiftUI のパネルはメモリを本来のドーナツとして表示する: 充填 = 使用率、色は
  メモリのカラーモードに従い、中央にパーセンテージ、その下に `used / total GB`。

## Consequences

- `SpinnerView.Spec` に種別 — スピナー（`rpm` で駆動）とゲージ（静的な `fill` で駆動） — が
  加わり、アニメーションの `step()` ループはゲージのセルを飛ばす。メニューバーのビューが 2 つの
  パラダイムを描くのはこれが初めてである。
- メモリは（GPU と違って）**常に取得できる**ので、degrade / フォールバックの経路が要らない —
  GPU の扱いより単純である。
- `AppSettings` に既存の寛容な `decodeIfPresent` パターンで `showMemory`（デフォルト off）が
  加わる。以前に永続化された設定はそのまま読める。
- メモリはスピナーのグローバルな `colorMode` を共有するのではなく、独自の `memoryColorMode`
  （`ColorMode { fixed, gradient }` enum を流用、デフォルト `gradient`）と `memoryColorHex`
  アクセントを持つ — 色を独立に設定できるようにするためである。グラデーションは
  `memoryGradientStops`（青 → 緑 → オレンジ → 赤）を通して使用率で駆動され、スピナーの負荷
  グラデーションとは別物である。どちらも汎用の `gradientColorHex(at:stops:)` 補間器を共有する。
- メモリは 3 分間の履歴折れ線チャートに 3 本目の線として**描画される**（使用率 %、0...100 の
  軸を共有）。色は CPU の緑・GPU の青とは区別できる固定色である。`AppModel` に `cpuHistory` /
  `gpuHistory` と並んで `memoryHistory` バッファが加わり、凡例にメモリのチップが加わる。
  （線はゆっくり動くが、この区間でリークやじわじわとした増加が見えるようになる。）
- 新しい純関数とマッピングは `LoadSpinnerCoreTests` で網羅する（`memoryReading` の導出、
  `memoryGaugeColorHex` の固定／グラデーションのマッピング、新しいフィールドの寛容なデコード）。

## Alternatives considered

- **プレッシャー帯による色付け（カーネル由来の緑／アンバー／赤）。** ゲージの色と 正常 / 警告 /
  逼迫 のピルとして短期間出荷した。macOS が下す余裕についての権威ある判定であり、充填とは独立
  しているので 2 つ目のシグナルを運べたはずだが — 直感的でないと分かった: リングが目に見えて
  満杯でも色は「normal」でありうるし、「使用率は高いがプレッシャーは低いので大丈夫」は人が
  ゲージを読むやり方ではない。固定／使用率グラデーションの軸を採り、色・ピル・
  `kern.memorystatus_vm_pressure_level` の読み取りを端から端まで取り下げて、ゲージ全体を
  使用率中心に保った。
- **プレッシャーを充填に使う（3 段階のゲージ）。** 使用率ではなくプレッシャーのレベルまで
  リングを埋めることを検討した。不採用: プレッシャーは 3 段しか無いので充填が粗く飛び、ゲージの
  存在理由そのものである連続的な「どれだけ埋まっているか」という読みを捨てることになる。
- **メモリを `DisplayMode` に畳み込む。** CPU/GPU と統一的ではあるが、モードの行列が爆発し
  （max/cpu/gpu/both × メモリ）、メモリを CPU への *追加* ではなく *代替* として誤って表す。
  独立したトグルを採って不採用とした。
- **ゲージをアニメーションさせる（例: プレッシャー下で脈動させる）。** レートとレベルの言語を
  濁らせる。基本形からは外した。critical 帯のアラートとしての脈動は、別途あらためて検討しうる。
- **メニューバーのリングの横に数値を出す。** 試作した（ゲージの横に「63%」を描く
  `memoryShowValue` トグル）が、~22px のリングの横の数値は読むには窮屈すぎたので取り除いた。
  代わりにパネルのドーナツが穴の中にパーセンテージを載せる。
